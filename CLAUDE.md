## Project Overview

This repository contains a production-ready setup for deploying **Velero** on **Azure Kubernetes Service (AKS)** via **ArgoCD** (GitOps). It includes cost-optimized Azure storage configuration, CSI-based PVC snapshots, automated backup schedules, and supporting shell scripts.

## Key Configuration Files

### `velero/values.yaml`
Central Helm values file. Before deploying, replace these placeholders (done automatically by `setup-azure.sh`):
- `<REPLACE_WITH_YOUR_RESOURCE_GROUP>`
- `<REPLACE_WITH_YOUR_STORAGE_ACCOUNT>`
- `<REPLACE_WITH_YOUR_SUBSCRIPTION_ID>`

Notable settings:
- Velero image: `v1.13.0`; Azure plugin: `v1.9.0`; CSI plugin: `v0.7.0`
- Uploader: `kopia` (more efficient than restic)
- Node agent disabled by default (cost saving; enable only for volumes without snapshot support)
- Daily backup: `0 2 * * *` (30-day TTL); Weekly: `0 3 * * 0` (90-day TTL)
- Excludes `kube-system`, `kube-public`, `kube-node-lease` from scheduled backups

### `argocd/velero-application.yaml`
Deploys Velero from the upstream Helm chart at `targetRevision: 6.7.0`. Update the revision when upgrading Velero.

### `config/config.env` (git-ignored)
Generated by `setup-azure.sh`. Contains real Azure credentials — **never commit this file**.

## Common Tasks

### Initial Setup
```bash
cp config/config.example.env config/config.env
# Edit config/config.env with your Azure values
chmod +x scripts/setup-azure.sh
./scripts/setup-azure.sh          # Creates Azure resources, k8s secret, updates values.yaml
kubectl apply -f argocd/velero-application.yaml
```

### Verify Deployment
```bash
./scripts/verify-installation.sh
kubectl get pods -n velero
kubectl get backupstoragelocation -n velero
```

### Manual Backup / Restore
```bash
velero backup create my-backup --include-namespaces=production
velero backup get
velero restore create --from-backup my-backup
```

### Run Smoke Test
```bash
./scripts/test-backup-restore.sh   # Creates test workload, backs up, deletes, restores
```

## Sensitive Files — Never Commit
The `.gitignore` already excludes these; double-check before any commit:

## Azure Cost Optimizations in Place
- Storage tier: `Standard_LRS` (cheapest redundancy)
- Lifecycle policy: Hot → Cool (30 d) → Archive (90 d) → Delete (180 d)
- Incremental managed-disk snapshots only
- Node agent (`deployNodeAgent: false`) disabled

## Security Notes
- Velero pods run as non-root (`runAsUser: 65534`, `runAsNonRoot: true`)
- Container drops all Linux capabilities, uses read-only root filesystem
- Storage account: HTTPS-only, TLS 1.2 minimum, public blob access disabled
- Prefer Managed Identity over storage-key auth when hardening further (see README)

## Prerequisites
- `az` CLI authenticated to the correct subscription
- `kubectl` configured against the target AKS cluster
- `helm` 3.x
- ArgoCD installed in the cluster
- Azure RBAC: Storage Account Contributor + Disk Snapshot Contributor on the resource group
